# self-review

これからコミットする変更のセルフレビューを監督する。レビュー自体は読み取り専用のサブエージェントに実行させ、このスキルは実施回数の管理・打ち切り・記録・レビュー結果の扱いを担当する。

git worktree で作業している場合（作業ディレクトリが `.claude/worktrees/` 配下）は、以下の git コマンドと `round.sh` / `log.sh` に worktree のパスを渡す（`git -C <worktree-path> ...` / `bash ${CLAUDE_SKILL_DIR}/round.sh <worktree-path>` / `bash ${CLAUDE_SKILL_DIR}/log.sh finding <worktree-path> ...`）。また可能な限り `&&` でコマンドを連結せず、1 コマンドずつ実行する。

## 1. レビューする変更があるか確認する

`git status --porcelain -uall` を実行する。**未コミットの変更が無ければ、その旨を報告して終了する**（以降の手順は実行しない）。

## 2. 実施回数を確認する

```bash
bash ${CLAUDE_SKILL_DIR}/round.sh
```

- `proceed` → 手順 3 へ進む。
- `stop` → **レビューは実施しない。** このコミットに割り当てたレビュー回数を使い切ったことを伝え、手元にあれば直前のラウンドで見送った指摘と、選べる道（このままコミットする／残った指摘を直す／方針を決める）を添えて、次の一手をユーザーに委ねる。往復が止まらないのは判断材料がリポジトリにも会話にも無いからで、それを持っているのはユーザーだけ。回数を使ったのが今の変更とは限らない（同じコミットの上で作業をやり直せば、破棄した変更が使った分を引き継ぐ）ので、収束しなかったと決めつけない。
  - ユーザーがレビューの続行を選んだときに限り、状態ファイル（`git rev-parse --absolute-git-dir` 配下の `self-review-rounds`）を消して数え直す。自分の判断では消さない。打ち切りを自分で解除できるなら、上限は無いのと同じ。

- `proceed` / `stop` 以外（コマンドが失敗した場合を含む）→ レビューは実施しない。回数を数えられなかったことをユーザーに伝え、指示を仰ぐ。

このコマンドはレビューを起動する前に回数を数え上げる。回数を自分で数えたり、状態ファイルを書き換えたりしない。打ち切りを避けるために数えないまま手順 3 に進むと、このスキルが持つ唯一の停止条件が消える。

## 3. レビューをサブエージェントに実行させる

Agent ツールで読み取り専用のサブエージェント（`subagent_type` は `Explore`）を起動し、結果をこのターンで受け取る（`run_in_background: false`）。プロンプトには次を渡す。

- `${CLAUDE_SKILL_DIR}/references/review.md` を読み、そこに書かれた手順でレビューすること。
- レビュー対象のリポジトリのパス（worktree で作業している場合はその worktree のパス）。
- 会話の中で決めた方針、ユーザーから受けた指示、まだ書かれていない要件のうち、今回の変更に効くもの。サブエージェントは会話履歴を持たないので、渡さなければリポジトリに根拠が無いものとして `要判断` で上がってくる。

Agent ツールが使えない環境では、このスキル自身が `references/review.md` を読んでレビューする。会話履歴から切り離せない分だけ甘くなるが、レビューが走らないよりはよい。

## 4. 指摘を記録する

指摘があれば、サブエージェントが各指摘に添えた記録用の要約を、指摘ごとに次のコマンドで記録ファイルに追記する。人間が後から指摘の傾向を振り返るための記録なので、報告する指摘がある回は必ず追記する。

```bash
bash ${CLAUDE_SKILL_DIR}/log.sh finding \
  --category '<区分>' \
  --reference '<観点ファイル名>' \
  --perspective '<見出し>' \
  --finding '<記録用の要約（指摘内容）>' \
  --basis '<記録用の要約（根拠）>'
```

- 区分・観点ファイル名・見出しは報告されたものを、指摘内容と根拠はサブエージェントが添えた記録用の要約をそのまま入れる。自分で要約し直すと、記録と報告が食い違う。
- 指摘ごとにこのコマンドを繰り返す。どのラウンドの指摘かは手順 2 が残した id から付くので、渡さない。ラウンド自体は手順 2 が記録しており、指摘が無かった回もそこに残る。
- 値に含まれるシングルクォートは `'\''` に置き換えて埋める。括りが途中で閉じるとコマンドごと失敗し、その指摘は記録されない。
- 値の中にコミットコマンドの文字列を書き写さない。コミットを止めるフックがそこを本物のコミットと見て deny し、その指摘の記録が落ちる。
- 同じ指摘が次のラウンドでも報告されたら、その都度追記する。1 行は「この指摘をこの時刻に報告した」という事実なので、繰り返しは重複ではなく、見送られた指摘が再び上がったという情報になる。
- 溜まった記録は `bash ${CLAUDE_SKILL_DIR}/log.sh report` で読む。区分と観点の分布、同じコミットで複数ラウンド上がった観点（同じ指摘の再提示には印が付く）が出る。記録する項目とその置き場所の理由は `log.sh` 冒頭のコメントにある。

## 5. レビュー結果を扱う

指摘は区分・観点・根拠を落とさずに伝え、指摘ごとに判断する。サブエージェントが添えたコミット・PR の案内も併せて伝える。

- `欠陥` は、直さないと何が起きるかを見て、直すか見送るかを決める。**見送るならそう言う。黙って落とさない。**
- `要判断` は、サブエージェントが指摘ごとに添えた扱いに従う。
- 修正を入れたらこのスキルをもう一度呼んでよい。回数は手順 2 が数えており、収束しなければ打ち切られる。

残りのラウンド数はユーザーにもレビューの判断にも持ち込まない。あと何回で打ち切られるかが分かると、指摘を判断するより打ち切りまで耐える方が安くなる。
