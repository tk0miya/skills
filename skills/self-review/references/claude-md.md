# CLAUDE.md レビュー観点

`CLAUDE.md` を変更した場合に、共通観点に加算する。CLAUDE.md は毎セッションでコンテキストに読み込まれるため、書けば書くほど他の情報を圧迫する。

## 何を書くか

- プロジェクトの概要やビルド・テストの実行方法といった基本情報が書かれているか。
- 設計や開発方針といったドキュメントを書いていないか。それらは `.claude/rules/` や `docs/` 以下に置き、CLAUDE.md には基本情報以外を書かない。`.claude/rules/` と `docs/` のどちらへ置くかは、記述の内容に応じて判断する。
- 対応を見送った内容（検討したが採用しなかった案、今回はやらないと判断したこと）を書いていないか。開発者からの要請が無い限り不要。

## 分量

- 端的か。冗長な記述や同じ内容の言い換えを重ねていないか。
- 200〜300 行に収まっているか。超える場合は切り出しを検討する。

## プロジェクトの構造

- このプロジェクト特有の構造だけを説明しているか。言語やフレームワークの一般的な構成は、モデルが既に知っているので触れる必要はない。
- 紹介する場合もディレクトリの構造に留め、ファイル一覧を列挙していないか。
