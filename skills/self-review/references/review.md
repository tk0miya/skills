# レビュー手順

`self-review` スキルから起動されたサブエージェントが従う手順。これからコミットする変更をレビューし、結果を起動元へ返す。パスはいずれもこのファイルと同じディレクトリからの相対。

## 1. レビュー観点を組み立てる

同梱の観点ファイルを読み込む。

- **常に** `common.md` を読む。
- 判定材料に該当する観点ファイルがあれば追加で読む（複数該当すれば全て加算）。

| 判定材料 | 追加で読む観点 |
|---|---|
| `Gemfile` または `*.gemspec` がある | `ruby.md` |
| `skills/**/*.md` を変更している | `skill-review.md` |
| `README*` / `CHANGELOG*` などのドキュメントを変更している | `docs.md` |
| `CLAUDE.md` を変更している | `claude-md.md` |
| `.claude/rules/**` を変更している | `rules.md` |

## 2. 変更をレビューする

`git status --porcelain -uall` と `git diff HEAD`（必要に応じて `git diff --staged`）で、最後のコミット以降の未コミット変更を確認する。未追跡ファイルは `git diff HEAD` に現れないので内容を直接読む（`-uall` を付けないと未追跡ディレクトリが 1 行に畳まれ、配下のファイルが分からない）。

まずプロジェクトの規約と慣習を把握してから、組み立てた観点でその変更をレビューする。規約は CLAUDE.md と `.claude/rules/**` にあり、後者は frontmatter の `paths` が変更したファイルにマッチするものを読む。このエージェントは CLAUDE.md も `.claude/rules/**` も会話の履歴も自動では読み込まないので、起動元から渡された方針と自分で読んだファイルだけが判断材料になる。規約を読まないまま指摘すると、そこで既に決着している点を蒸し返す。

git worktree で作業している場合（起動元から worktree のパスを渡された場合）は、git コマンドは `cd <path> && git` ではなく `git -C <worktree-path>` を使う。また可能な限り `&&` でコマンドを連結せず、1 コマンドずつ実行する。

## 3. 起動元に報告する

指摘があれば（`要判断` だけの場合も含めて）、指摘ごとに次の項目を添えて、指摘内容（と必要なら修正案）を返す。**根拠を書けないものは報告しない。** 起動元はこの項目で何を直してコミットするかを判断するので、どれも省略しない。

- **区分**：`欠陥`（直さないと何が起きるかを書けるもの）か `要判断`（どちらの選択も成立し、リポジトリ内に根拠（CLAUDE.md・要件・既存コードの慣習）が見つからないもの）か。
- **観点**：手順1で読んだ観点ファイルのどの見出し（`Correctness` / `Testing` / `Comments` など）に基づく指摘か。
- **根拠**：`欠陥` なら直さないと何が起きるかを一文で。`要判断` なら選択肢と判断材料を書き、どちらかを選ばない。
- **記録用の要約**：指摘内容と根拠を、それぞれ 1 行で読める長さに要約したもの。起動元がこの 2 行をそのまま記録ファイルへ書く。報告本文を要約し直させると、記録が報告と食い違う。

`要判断` は起動元またはユーザーが決めるものなので、次の扱いを添えて返す。区分の名前だけでは何をすべきかが伝わらず、既定で「直す」に流れる。

- レビューには見えない根拠（ユーザーの依頼、会話の中で決めた方針、まだ書かれていない要件）を起動元が持っているなら、その根拠が支持する側を選ぶ。現状と違えば直し、現状のままなら維持する。今後も効く判断なら、次のレビューが読む場所に根拠を残す（CLAUDE.md・`.claude/rules/`・その記述が効くコード中のコメントのうち、内容に応じた場所）。同じ点はそれ以降 `要判断` として上がってこない。
- そうした根拠が無いなら現状維持を選ぶ。根拠の無い選択はレビューが走るたびに選び直され、次の回では逆側が選ばれて往復になる。
- 要件や意図が必要で判断できないものは、ユーザーに委ねる。

コミットに進むかどうかは指摘を受けた起動元が決めるので、指摘の有無や区分に関わらず、`commit.md` の方針に従って、どうコミット・整理し、この後どう PR を作成・更新するのが良いかを、起動元が同ファイルを読まずに実行できる粒度で併せて伝える。区分ごとに出し分けると、`欠陥` を見送ってコミットする回に案内が届かない。
