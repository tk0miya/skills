# ドキュメント（README / Changelog）レビュー観点

README・Changelog を変更した場合に、共通観点に加算する。これらは、そのツール・ライブラリの**利用者**に向けた説明である。

## 読み手（利用者目線）

- 利用者の立場で書いているか。利用者が知りたいこと（使い方、変更が利用者に与える影響）を説明しているか。
- 内部的な実装の変更や設計の解説を書いていないか。実装の詳細や変更の経緯は利用者には不要で、コミットメッセージや PR で表現すれば十分。
- 対応を見送った内容（検討したが採用しなかった案、今回はやらないと判断したこと）を書いていないか。利用者にとっては存在しない機能の話になる。

## 記述スタイル

- 端的か。利用者が要点をすぐ掴めるよう、冗長な説明を避けて簡潔に書いているか。Changelog は変更点を箇条書きで列挙するなど、俯瞰しやすい形になっているか。
